Quickstart

1. Create an app in the console and add your site's origin. You get a pk_test_… publishable key and a sk_test_… secret key.

2. Add the button:

<script src="{{.BaseURL}}/sdk/singleton.js"></script>
<div id="verify"></div>
<script>
  Singleton.button("#verify", {
    publishableKey: "pk_test_…",
    required: ["human", "age_over_18"],
    reference: currentUser.id
  }, async (err, result) => {
    if (err) return showError(err.message);
    await fetch("/singleton/complete", { method: "POST", body: result.token });
  });
</script>

3. Verify the token on your server (any JOSE library that supports EdDSA):

import { jwtVerify, createRemoteJWKSet } from "jose";
const JWKS = createRemoteJWKSet(new URL("{{.BaseURL}}/.well-known/jwks.json"));

app.post("/singleton/complete", async (req, res) => {
  const { payload } = await jwtVerify(req.body, JWKS, { audience: "app_…", issuer: "{{.BaseURL}}" });
  if (payload.status === "duplicate") return res.status(409).send(`Already registered as ${payload.duplicate_of}`);
  await users.update(payload.reference, { humanId: payload.sub, verified: payload.predicates });
  res.sendStatus(204);
});

Concepts

TermMeaning
HolderA person with a Singleton Pass: a key on their device that was enrolled after one verification.
ScopeYour app's namespace (e.g. app:acme-4f1a). Pseudonyms are unique inside a scope and unlinkable across scopes.
ActionAn optional sub-scope (drop:fall-tour, poll:42) that gives each human one participation per action.
Nullifier / pseudonymThe stable 32-byte identifier of a holder inside one scope. Store it as your "human id".
PredicateA yes/no fact proven by membership in a published set: human, over 18, issued in AU…
EpochA sealed snapshot of every set, committed with Merkle roots anchored on-chain. Proofs reference an epoch; the current and {{"previous"}} epochs are accepted.

JavaScript SDK

Singleton.verify(options) → Promise<Result> opens the hosted consent screen in a popup (falling back to a redirect) and resolves when the holder finishes.

OptionType
publishableKeystringRequired. Works only from origins allowed on the app.
requiredstring[]Predicates; defaults to the app's defaults.
actionstringOptional one-per-human action scope.
referencestringYour account id; enables duplicate detection.

Rejections carry error.code: declined, closed or unqualified (with error.missing).

Sessions API

POST /v1/sessions

Authorization: Bearer sk_… (server) or Bearer pk_… (browser, allowed origins only).

{
  "required": ["human_doc", "age_over_18"],
  "action": "drop:fall-tour",       // optional
  "reference": "user_123",          // optional, enables duplicate detection
  "returnUrl": "https://acme.com/after"  // optional, for redirect flows
}
→ 201 { "id": "vs_…", "url": "{{.BaseURL}}/verify/vs_…", "challenge": "…", "status": "pending", "expiresAt": "…" }

GET /v1/sessions/:id

Secret key only. Returns the session; once status is verified or duplicate it includes a fresh token.

statusmeaning
pendingWaiting for the holder.
verifiedPredicates proven. returning: true if this human was seen in this scope before.
duplicateProven, but the human is already bound to another reference (duplicateOf).
failedInvalid proof, expired epoch, replay, or missing predicate.
expiredNot completed within 15 minutes.

Result tokens

Compact JWS, alg: EdDSA (Ed25519), key id {{.KeyID}}, valid 10 minutes. Verify against /.well-known/jwks.json.

{
  "iss": "{{.BaseURL}}", "aud": "app_…", "sub": "<nullifier>", "sid": "vs_…",
  "scope": "app:acme-4f1a#drop:fall-tour", "predicates": ["human_doc"],
  "status": "verified", "duplicate": false, "duplicate_of": "", "returning": false,
  "reference": "user_123", "iat": 1760000000, "exp": 1760000600
}

Stateless verify

Native apps can run their own challenge and post the holder's presentation directly: POST /v1/presentations/verify with { presentation, challenge, required, action }. The challenge must be ≥ 16 random characters you generated and never reused.

Agent delegation

A holder can deputise an AI agent inside your scope. The agent holds an Ed25519 key; the delegation is a ring-signature presentation bound to the statement's hash, so you learn the pseudonym it acts for — not who that is.

POST /v1/delegations   (pk or sk)
{ "delegation": { "v": 1, "scope": "app:acme-4f1a", "agent": "<ed25519 pubkey hex>", "label": "Scheduling assistant",
                  "permissions": ["events:create"], "issuedAt": 1760000000, "notAfter": 1760604800 },
  "presentation": { … } }

POST /v1/agents/verify (sk)
{ "delegationId": "dlg_…", "message": "<the exact request bytes>", "signature": "<base64url Ed25519>" }
→ { "valid": true, "nullifier": "…", "permissions": ["events:create"], "notAfter": "…" }

Webhooks

Events: session.verified, session.duplicate, session.failed, delegation.created. Header Singleton-Signature: t=<unix>,v1=<hex HMAC-SHA256(secret, "t." + body)>. Reject signatures older than five minutes. Retries: 3 attempts, 1s / 3s backoff.

Errors & limits

Errors are JSON { "error": "…" } with conventional status codes (400 validation, 401 bad key, 403 origin not allowed, 404, 409 duplicate enrolment, 429 rate limited). Default limits: 600 session or verify calls per minute per IP; contact us for more.

Protocol

Group: ristretto255. A holder key is x, P = x·G. For scope s, H_s = HashToGroup(s) and the key image is I = x·H_s; the nullifier is SHA-256("singleton/nullifier/v1" ‖ I).

A proof is a bLSAG-style linkable ring signature over a ring R drawn from the epoch's predicate set. It shows knowledge of x with P_j = x·G for some P_j ∈ R and I = x·H_s, and binds the scope, the verifier's challenge, the epoch, the set name and the bucket prefix into every challenge hash.

Rings are canonical anonymity buckets: holders are placed in a prefix tree by SHA-256("singleton/bucket/v1" ‖ P); a bucket is all set members sharing the first b bits, with at least 32 members. Because buckets are stable across epochs, repeated proofs reveal at most the bucket. Verifiers rebuild the ring from the published set and reject buckets below the minimum size.

Properties: same holder + same scope ⇒ identical nullifier; different scopes ⇒ unlinkable (DDH); no holder can forge membership or another holder's key image; replays fail because the challenge is session-bound. v2 replaces buckets with a zk-SNARK over the whole set.

Auditing the network

Each epoch's set roots are anchored by HumanRegistry.anchorEpoch(uint64, bytes32[], bytes32[], uint64[]). Download any set and recompute its Merkle root:

curl {{.BaseURL}}/api/sets/<epoch>/human | jq .root
go run ./cmd/singleton verify-root -url {{.BaseURL}} -set age_over_18

See the transparency explorer for epochs, anchor transactions, attesters and revocations.
